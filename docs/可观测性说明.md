# 可观测性说明

应用通过匿名 `GET /metrics` 输出 Prometheus 文本指标。生产环境应在反向代理中仅允许监控网段访问该路径。

建议 Prometheus 抓取配置：

```yaml
scrape_configs:
  - job_name: mediaforge
    metrics_path: /metrics
    static_configs:
      - targets: ["mediaforge:3000"]

rule_files:
  - /etc/prometheus/rules/mediaforge.yml
```

将 `monitoring/prometheus-alerts.yml` 安装到上述规则目录，并由 Alertmanager 配置通知渠道。

主要指标：

- `mediaforge_pg_pool_size`、`mediaforge_pg_pool_available`、`mediaforge_pg_pool_waiting`
- `mediaforge_pg_pool_wait_seconds`、`mediaforge_pg_query_seconds`
- `mediaforge_pg_slow_queries_total`、`mediaforge_pg_active_connections`、`mediaforge_pg_lock_waiting`
- `mediaforge_minio_operation_seconds`、`mediaforge_minio_failures_total`
- `mediaforge_minio_bucket_catalog_bytes`、`mediaforge_minio_bucket_catalog_objects`
- `mediaforge_background_failures_total`、`mediaforge_background_runs_total`
- `mediaforge_transient_retries_total`

`bucket_catalog_bytes` 是 PostgreSQL 文件目录中有效对象的总大小，不代表 MinIO 集群磁盘总容量；集群物理容量应同时接入 MinIO 自带的 Prometheus 指标。

慢查询阈值由 `DATABASE_SLOW_QUERY_THRESHOLD_MS` 控制，默认 `500` 毫秒。应用日志不会记录 SQL 文本或参数，只记录操作类型和耗时。文件写入、删除日志包含 `request_id`、`user_id` 和 `file_id/object_id`，便于跨日志定位单次请求。

瞬时故障重试默认最多尝试 3 次，可通过以下变量调整：

```env
TRANSIENT_RETRY_MAX_ATTEMPTS=3
TRANSIENT_RETRY_BASE_DELAY_SECONDS=0.2
TRANSIENT_RETRY_MAX_DELAY_SECONDS=1
TRANSIENT_RETRY_JITTER_SECONDS=0.1
```

只有 PostgreSQL 连接获取失败，以及 MinIO 连接超时、网络错误和临时 5xx 会重试。已经开始的 SQL/事务、权限、配额、格式和资源不存在错误不会自动重试。
