# 视频公网 URL 系统 VibeCoding 开发计划

本计划将 [设计方案](视频公网URL生成管理系统设计方案.md)拆成可逐轮交给编码助手执行的任务卡。只完成 **MediaForge 仓库内的代码、配置模板、脚本、开发环境测试与文档**。仓库内实现已完成，下面的任务卡保留约束与验收标准；实际状态、测试证据及未验证项见第 8 节。

**开发环境背景：开发环境与生产环境位于两台独立机器。** 编码、调试和本计划中的测试均在开发机或隔离测试环境执行，不连接生产数据库、MinIO 或队列。下文“本地”指开发机上的测试环境，不是生产机上的回环访问。

按 2026-11-12 用户要求，CI 恢复原状：撤回本轮新增工作流、原 Playwright 工作流修改及相关忽略规则例外。当前只保留本地测试与验收，不新增或启用 GitHub Actions；后续引入 CI 另行规划。

开发环境已按 [开发环境完整部署流程](开发环境完整部署流程.md) 统一使用 Docker Compose。日常联调复用开发 PostgreSQL/MinIO，授权库和读取账号独立；自动集成、权限及故障测试在一次性隔离容器中运行，不修改日常服务。V02 保留可重复测试基线，宿主机无需安装 Python、Node、数据库或 FFmpeg。

不纳入本计划：IT 人员的工作、公网 IP/DNS/端口映射、防火墙或公司网络配置、正式证书申请与续期、生产安装/发布/灰度/值守交接。实际公网访问和真实供应商付费调用不作为仓库内完成条件，也不能用本地测试宣称它们已验证。

## 1. 最终要做成什么

```text
调用端 → 现有 Nginx 的专用下载配置 → 新增 media-gateway
       → 校验短期链接 → 只读访问 MinIO → 流式返回视频
```

| 范围 | 开发结果 |
| --- | --- |
| gateway | 一个独立下载服务，支持鉴权、HEAD、GET、Range、限流量及资源回收 |
| 授权数据 | 复用 PostgreSQL 实例，新增授权 database、迁移脚本和专用角色，不新增数据库服务 |
| API / Worker | 共用签发与撤销逻辑，视频提交前自动申请链接，任务与权限变化时正确失效 |
| 管理页面 | 外发链接管理用户按权限查看、签发、轮换、撤销，管理员管理策略与批量撤销 |
| 配置交付 | gateway 镜像/Compose 定义、Nginx 站点模板、独立环境模板及最小 MinIO 读取策略 |
| 测试交付 | 基于开发机真实 PostgreSQL/MinIO 的独立测试资源、模拟供应商、本地端到端、安全与资源回收测试 |

沿用设计边界：不复制视频、不建本地导出目录；正式架构只新增 gateway 容器，复用宿主机 Nginx；画布原有预览/下载继续走原流程。测试可以临时启动 Nginx 容器验证模板，这不代表新增生产 edge 服务。

## 2. 每轮怎样让编码助手工作

后续增量开发一次执行一张任务卡。先确认前置任务及实际代码，再完成该轮功能、必要测试和记录；不重复生成已完成部分，不使用空接口、固定成功响应或永久 mock 代替实现。本次按用户要求连续执行了完整计划。

可直接使用以下提示词，把任务编号替换为当前任务：

```text
请执行 docs/视频公网URL生成管理系统开发计划.md 的 V01。
先读取任务卡、设计约束、相关现有代码及已完成记录，然后直接实现本轮任务。
只修改本轮所需内容；沿用仓库结构，不重构无关业务，不操作生产或外部基础设施。
完成代码及有意义的测试；修复本轮发现的问题，并检查对旧功能的影响。
如果依赖缺失，继续完成不依赖它的工作，准确记录未验证项，不用 mock 通过冒充真实集成通过。
结束时说明改动文件、实际测试命令与结果、剩余问题，并更新该任务的完成记录。
```

后续轮次在同一代码状态继续，不重复生成已完成模块。任务卡所列路径是建议修改范围，编码前仍需查找真实调用链；必要的相邻改动可以做，但要在记录中说明理由。前置任务未通过时先修复前置缺口，不带着已知权限或一致性问题进入后续接入。

### 每轮固定交付

- 可运行、可审查的功能改动，以及相应失败路径；不使用 TODO 分支充当完成。
- 验证实际行为的测试结果，明确区分单元 mock、真实本地依赖、未运行和失败。
- 一条完成记录：任务 ID、改动文件、验证命令/结果、未解决项和下一轮入口。

功能测试通过且没有未解决的关键安全问题后，才能将任务标为“已完成”。仅因外部工具不可用，不必停止所有工作，但需要真实依赖证明的任务只能记“部分完成/待验证”。

## 3. 编码期间始终遵守的约束

| 约束 | 实现要求 |
| --- | --- |
| 默认关闭 | `PUBLIC_VIDEO_ENABLED=false` 时，旧应用不依赖授权库启动；本地视频外发明确失败，不退回旧 URL 拼接或全局 Token |
| 最小权限 | gateway 不导入 `main.py`、不启动 Worker/维护任务，不获得业务库、Redis、供应商或 `APP_SECRET_KEY` 凭据；独立 MinIO 只读账号 |
| 服务端授权 | 文件存在不等于有外发权限；校验 owner、共享范围、任务引用、供应商权限与素材外发许可 |
| 固定对象 | 绑定具体非空版本；无稳定版本时要求不可覆盖并在 GET 上使用 If-Match，不静默读最新版本 |
| 凭证保密 | 32 字节安全随机 token，只长期保存摘要；明文不进入通用任务、历史、日志、浏览器持久化或普通幂等缓存 |
| 每请求校验 | HEAD/GET/Range 均在线校验并原子扣减预算，无凭证和失效凭证不得访问 MinIO，依赖故障拒绝访问 |
| 有界传输 | 独立读取池与连接池、固定块大小、有限预取、客户端反压、总时限、断连回收；视频不整段入内存、不落盘 |
| 不扩展范围 | 不做匿名桶、任意 URL 转发、CDN、视频转码或每链接动态创建 IAM 策略；不承诺未实现的在途立即撤销 |

初始参数沿用设计方案：默认 TTL 30 分钟、普通上限 2 小时、视频不超过 500 MiB 且满足模型限制、并发 16、单块 256 KiB、最多预取 2 块、总时限 600 秒。单链接 GET/HEAD 各 64 次；每次 GET 保守预扣完整文件大小，断连不自动退款，另设全局预算。资源限制必须实际生效，不能只定义配置名。

## 4. 任务地图

```text
V01 契约与配置 → V02 开发机集成测试基线 → V03 授权库与角色
→ V04 原子准入 → V05 存储读取 → V06 签发服务
→ V07 管理 API → V08 可靠撤销 → V09 HTTP 协议
→ V10 gateway 流式传输 → V11 供应商提交接入
→ V12 生命周期闭环 → V13 管理页面
→ V14 仓库配置与可观测性 → V15 本地全链路验收
```

顺序用于单会话持续开发，不按人员/周次排期。每轮以完成标准判断结束，复杂任务可以拆成连续子轮，但不得跳过验证。

### V01：梳理调用链，建立契约与独立配置

**前置：无。范围：`main.py`、现有权限/存储代码，新增 `app/public_media/config.py`、`contracts.py`。**

- [x] 列出 Cloudwise/Seedance、火山素材和其他视频 URL 提交路径，区分内部相对引用、本应用绝对地址、已有公网 URL 和 Asset ID，记录到本文件的完成记录。
- [x] 明确来源/授权状态、URL、请求字段与 HTTP 错误契约；多段 Range 首版返回 416。
- [x] 实现签发端与 gateway 分离的配置类型、默认值和范围校验，地址来自受控配置；不修改旧 `DATABASE_URL` 或 `PUBLIC_MEDIA_BASE_URL`。
- [x] 将外发操作权限与页面访问权限区分，定义默认拒绝规则；对无法证明有权外发的共享/敏感素材先拒绝。

**完成标准：** 配置单测覆盖非法值、开关关闭及缺配置；独立模块不因未提供主应用密钥而导入失败；接口规则没有待猜测的关键授权语义。

### V02：基于容器建立隔离集成测试基线

**前置：V01。范围：开发 Compose 扩展、隔离测试镜像、fixtures、初始化/清理与运行说明。**

- [x] 日常联调接入现有开发 Compose，授权库、角色和 MinIO 读取权限独立；不复制生产配置。
- [x] 自动测试在一次性容器内运行真实私有 PG16/MinIO/Nginx/gateway，随机回环端口，不挂载日常数据卷或 Docker socket。
- [x] 自动生成无敏感 MP4/MOV、已知字节和哈希，独立有版本/无版本桶，退出后清理本次进程及容器。
- [x] 明确集成开关，缺依赖失败；不能把跳过算作通过。
- [x] HBA、凭据轮换、依赖故障和恢复测试仅操作隔离资源，不停止日常共享服务。
- [x] 增加实际 gateway 与开发 HTTPS 镜像的独立 Compose 验收入口，测试网络不发布宿主机端口。

**完成标准：** `./scripts/dev.sh media-test` 可重复运行；镜像链路用 `media-smoke` 验证。开发业务数据保持完整，宿主机无需安装测试依赖。

### V03：授权库迁移、角色和独立连接池

**前置：V02。范围：`app/initialize.py`、`app/public_media/bootstrap.py`、`schema.sql`、`repository.py`、开发 Compose 和数据库集成测试。**

- [x] 实现显式初始化/版本迁移，创建 `media_sources`、`media_grants`、`media_policy_state`、`media_access_events` 及约束/索引。
- [x] 统一初始化入口临时使用管理员凭据，适配已有数据卷；重复执行不轮换密码、不重启用禁用策略/账号。API/Worker 保留原业务初始化，启用外发时检查授权库；gateway 只检查，绝不执行 DDL。以受限版本函数实现 schema v3 就绪检查，并验证跨库访问拒绝。
- [x] 新建授权库连接池，分开 writer/validator 配置，限制连接数/等待/SQL/锁超时；不复用业务库全局池或切换其 DSN。
- [x] 保证外发关闭时原 API/Worker 无需连接新库，独立 gateway 只有自身必需配置。

**完成标准：** 迁移可重复执行并记录版本；真实角色不能越权读取/写入；连接池能正常启停并在故障时快速失败，旧应用默认启动回归通过。

### V04：原子鉴权与配额准入

**前置：V03。范围：授权库函数、repository 调用与并发测试。**

- [x] 实现 `validate_and_admit`，按数据库时间校验摘要、状态、期限、全局开关。
- [x] 在同一事务按固定锁顺序检查并扣减链接及分层请求/流量预算；失败不返回对象快照，不重置已有预算。
- [x] 固定安全 search_path/schema，撤销 PUBLIC 函数执行权；gateway 仅获得受限函数执行与追加审计入口。
- [x] 摘要验证符合恒定时间比较要求，不暴露无 token 的对象枚举接口。

**完成标准：** 真实 PostgreSQL 并发请求不超发；错误/过期/撤销凭证、预算耗尽及故障结果正确；校验角色不能签发、续期或修改撤销状态。

### V05：独立 MinIO 读取组件

**前置：V02/V03。范围：`app/public_media/storage_reader.py`。**

- [x] 使用专用读取账号和固定 endpoint/桶/前缀白名单，支持 STAT、指定版本、条件 GET 和 offset/length。
- [x] 验证非空版本、大小与 ETag；无稳定版本走不可覆盖 + If-Match，不把 ETag 当 SHA-256。
- [x] 读取使用独立有界执行器/连接池与固定块大小；不用业务 `get_object_bytes()`、`materialize_media_url()` 或缓存下载方法。
- [x] 实现异常/超时/取消后的响应关闭与连接回收，不跟随重定向、不接受客户端存储地址。

**完成标准：** 真实 MinIO 完整/区间字节正确；对象变化、缺版本、403 和阻塞读取可控；组件自身不需要业务用户会话、root 或供应商凭据。

### V06：签发、轮换和对象权限服务

**前置：V04/V05。范围：`app/public_media/service.py`、现有权限校验适配。**

- [x] 显式接收可信 owner/task/provider 上下文，校验文件归属/共享、外发许可、任务引用及供应商使用权限；`get_file_by_id()` 不作为权限证明。
- [x] 建立固定对象快照，检查格式/大小/保留期与受限账号可读性；TTL 不超过已知素材保留期限。
- [x] 生成随机 token/摘要，URL 只含随机授权 ID 与凭证；列表、事件及异常不返回明文 token 或内部对象地址。
- [x] 实现创建/轮换幂等与响应丢失后的明确行为；只存摘要时不伪造“找回原链接”，轮换立即作废旧凭证。
- [x] 在首次处理明文 URL 时就实现脱敏，不能留待后续界面接入后才修日志。

**完成标准：** 跨用户、仅能预览、无任务上下文、禁止外发的素材均无法签发；多任务/多供应商分别绑定，重试不产生失控的活动授权；日志中无测试 secret。

### V07：内网链接管理 API

**前置：V06。范围：新增 `app/routers/public_video_links.py`、主 API 路由注册。**

- [x] 实现下表接口，接入会话、CSRF、操作权限和分页；只在原业务 API 注册，gateway 不挂载。
- [x] 客户端不能指定 owner、桶键、版本、endpoint、token 或越权 TTL；管理员批量操作必须限定范围。
- [x] 创建、轮换、撤销和策略变化留审计，列表按权限过滤且不返回可复用的凭证。

| 接口 | 功能 |
| --- | --- |
| `POST /api/public-video-sources` | 通过文件/任务/供应商 ID 建立绑定 |
| `POST /api/public-video-sources/{id}/grants` | 按明确幂等/轮换语义签发 |
| `GET /api/public-video-grants` | 分页、筛选、状态及统计 |
| `POST /api/public-video-grants/{id}/revoke` | 幂等撤销 |
| `POST /api/admin/public-video-grants/revoke-batch` | 有范围的批量撤销 |
| `GET/PUT /api/admin/public-video-policy` | 查询/修改策略 |

**完成标准：** 直接 HTTP 请求也无法越权，CSRF 与非法字段测试通过；新增路由/表如影响 snapshot，按真实接口更新，不删除安全断言。

### V08：可靠撤销与跨库协调

**前置：V06/V07。范围：`app/public_media/lifecycle.py`、业务侧可靠事件/状态存储。**

- [x] 实现按文件、任务、用户、供应商撤销，使用跨进程的协调方式阻止撤销期间激活新授权，不只依靠 Python 内存锁。
- [x] 可靠保存待撤销/待对账状态，支持重试，处理两库间进程退出；权限撤回安全性不能只依赖 Redis TTL 或内存事件。
- [x] 撤销未完成时不能向用户报告删除/禁用已完整成功；授权库不可用时拒绝新的外发与相关破坏性完成确认。
- [x] 实现到期归档、额度释放与恢复后统一撤销；维护记录失败不延长链接，不删除原视频。

**完成标准：** 故障注入与签发/删除竞态下，不产生删除后重新激活的授权；操作可重入，重复撤销与恢复不会使旧链接复活。

### V09：HTTP 文件响应协议

**前置：V01/V05。范围：`app/public_media/http_stream.py` 的协议解析部分。**

- [x] 实现 GET/HEAD、单段闭合/开放/后缀 Range、206/416、Content-Length/Content-Range 和 MP4/MOV MIME。
- [x] HEAD 不读取内容体并忽略 Range；多段 Range 统一拒绝；稳定强 ETag 与 If-Range 不匹配时回退完整 200。
- [x] 定义安全头、通用 404、405/429/503，不返回 304、Cookie、MinIO 原始错误或存储跳转。

**完成标准：** 协议单测逐字节校验区间/长度，覆盖空/越界/超长输入、后缀边界、扩展名篡改和条件请求；条件头不能绕过鉴权。

### V10：独立 gateway 与有界流式传输

**前置：V04/V05/V09。范围：`app/public_media/gateway.py`、流式实现及独立进程测试。**

- [x] 新建独立 ASGI 启停入口，只开放固定下载路由，禁用 docs/OpenAPI/调试/管理页；健康接口仅供本地探测，不由下载站点代理。
- [x] 先校验 token/参数并准入，再访问 MinIO；错误或撤销 token 对存储零调用。配置总并发、池容量和等待上限。
- [x] 依据客户端写入速度反压读取，有限预取，不长期占用数据库连接；响应头发送前校验上游状态，已开始后失败只断流。
- [x] 实现客户端断连、存储连接/读取与写入空闲超时、总时限和 finally 回收，覆盖底层同步线程不能靠异步取消自动结束的问题。

**完成标准：** 无主应用密钥的独立进程可运行；真实 socket 慢读/断连/阻塞测试证明资源回收，不以 ASGI 内存测试替代；大视频内存不按文件大小增长且不落盘。

### V11：供应商提交前自动签发

**前置：V06/V10。范围：`main.py` 视频引用/提交分支、共用签发适配与相关供应商测试。**
