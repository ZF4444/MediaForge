# 公司内部部署改进建议（50 人以内）

> 评估时间：2026-06-05
> 评估对象：Infinite-Canvas（基于 FastAPI 的 AI 创作工作台）
> 评估场景：开放给公司内部不超过 50 人使用

## 核心结论

这个项目本质上是**单用户本地工具**，直接给 50 人内部使用前必须先解决几个问题。
关键证据：

- 服务绑定 `0.0.0.0:3000`，无身份认证（`main.py:11309`）
- CORS 完全开放：`allow_origins=["*"]` + `allow_headers=["*"]`（`main.py:68` 附近）
- 真实可用的 API Key 明文存放在 `API/.env`
- 画布 / 对话 / 历史均为全局共享的 JSON 文件，无用户隔离
- 启动方式为 `python main.py` 前台运行并自动打开浏览器（桌面工具模式）

---

## 🔴 必须改（安全与数据，否则会出事）

### 1. 没有任何身份认证
- 任何能访问该 IP 的人都能使用，无登录、无权限控制。
- 50 人共享意味着：任何人都能查看 / 删除别人的画布、对话、生成历史。
- **建议**：
  - **最省事**：前面挂反向代理（Nginx / Caddy）做 HTTP Basic Auth 或 SSO，应用本身不改动。
  - **应用内**：加 FastAPI 中间件做 token / session 校验。
  - 50 人规模，Basic Auth + HTTPS 即可满足。

### 2. API Key 明文硬编码并可能已进入 Git 历史
- `API/.env` 中包含真实可用的 ModelScope / RunningHub / 自定义 API Key。
- `.gitignore` 已写 `**/.env`，但需确认这些 key 是否已经进入 Git 历史（一旦推送过远程仓库即视为泄露）。
- **建议**：
  - 立即**轮换（重置）所有已暴露的 key**。
  - 确认 `git log` 中没有 `.env`。
  - 这些是**计费的共享 key**——50 人共用一个 key，任何人都能跑满额度 / 余额，需要用量监控或限额。

### 3. CORS 完全开放
- `allow_origins=["*"]` + `allow_headers=["*"]`。
- 内网环境配合认证尚可接受，但若将来暴露到更大网络即为风险点。
- **建议**：改成具体的内网域名 / IP。

---

## 🟠 强烈建议改（多用户数据隔离与稳定性）

### 4. 数据没有用户隔离 + 并发写入风险
- 画布、对话、历史都是全局共享的 JSON 文件
  （`data/canvases/*.json`、`history.json`、`asset_library.json`）。
- 50 人同时读写同一批文件存在问题：
  - 没有「这是我的画布」概念，所有人共用一个空间。
  - JSON 文件并发写入容易损坏（除非全程加锁，需进一步核实）。
- **建议**：
  - 至少按用户隔离数据目录。
  - 长期看 `history.json` 这种单文件全量读写在 50 人下会成为性能瓶颈，可考虑迁移到 SQLite。

### 5. 单文件 515KB 的 `main.py`
- 不影响运行，但出 bug 时难以维护。属于「能跑但难改」，优先级低于安全问题。
- **建议**：按功能模块逐步拆分。

---

## 🟡 部署与运维

### 6. 生产化部署
- 当前是 `python main.py` 前台运行 + 自动打开浏览器，是桌面工具模式。
- 50 人服务需要：
  - 用 systemd / supervisor / Docker 托管，崩溃自动重启。
  - 加 HTTPS（配合上面的反向代理）。
  - 将 `print()` 调试输出改成正规日志。

### 7. 许可证限制（请注意）
- README 明确：**禁止商用、禁止修改封装成商业产品**。
- 「公司内部使用」被允许（"可以自己使用和公司使用"）。
- 但若要二次开发，**必须保持开源并注明原作者**。
- 给公司使用前最好与作者确认用法在授权范围内。

---

## 建议的最小落地顺序

1. 轮换 `API/.env` 中所有暴露的 key，并确认未进入 Git 历史
2. 加认证（推荐 Caddy / Nginx 反代 + Basic Auth + HTTPS，应用零改动）
3. 做用户数据隔离（或至少明确「共享空间」的预期并备份 `data/`）
4. 用 systemd / Docker 托管 + 规范日志
