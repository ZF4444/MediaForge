# 前端访问与 SSO 登录说明

## 前端访问地址

开发环境前端访问地址：

```text
http://192.168.60.21:3000/
```

通过 SSO 参数直接登录并进入首页：

```text
http://192.168.60.21:3000/auth/sso?username=飞帆&user_id=ou_9991ec9cb01e04251020a5f7ca518932
```

浏览器会自动对中文用户名进行 URL 编码。若由程序拼接地址，应使用 URL 查询参数编码，避免用户名中的中文、空格或特殊字符破坏链接。

## SSO 参数

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `username` | 否 | 用户显示名称；示例为 `飞帆`。若未提供，则使用 `user_id` 作为名称。 |
| `user_id` | 否 | 外部身份系统提供的稳定用户标识。建议始终传入；若未提供，服务端会尝试从 `username` 派生标识。 |

至少需要提供一个有效的用户标识。服务端会清理 `user_id` 中不支持的字符，并将结果作为 MediaForge 用户标识。

## 登录流程

1. 浏览器访问 `/auth/sso` 并提交 `username`、`user_id` 查询参数。
2. 服务端为首次出现的用户创建账号；已有用户则同步其显示名称。
3. 服务端创建登录会话，并通过 `sid` HttpOnly Cookie 保存会话凭据。
4. 登录成功后，服务端以 HTTP 302 将浏览器重定向到 `/`。

该入口用于外部平台跳转登录，不需要前端额外调用登录 API。浏览器必须能够访问提供该地址的服务；局域网访问还要求客户端与服务器网络可达。

## 接入与安全注意

当前 `/auth/sso` 接口根据查询参数中的 `username` 和 `user_id` 建立会话，接口本身不验证参数是否由可信身份平台签发。因此，示例链接仅适用于受控的开发或测试环境；不能将可被任意访问的该入口当作生产环境的身份认证边界。

生产接入前，应由可信的统一身份认证链路保护此入口，例如在服务端验证身份平台签名和时效性，或只允许可信网关完成认证后转发请求。不要仅依赖隐藏 URL、局域网地址或前端校验来证明用户身份。
