## 三、关键约束分析：「页面/功能完全不变」

本次为**纯结构重构（行为零变更）**。基于此，对前后端给出不同的风险判断：

### 3.1 后端：风险可控、收益高 ✅
FastAPI 的 `APIRouter` 可将路由拆分到多个文件，而 **URL 路径、请求/响应模型、状态码完全不变**。这是安全的重构。

### 3.2 前端：风险高、收益相对低 ⚠️
两个 1.2 万行的 JS 文件目前依赖**全局变量互相调用**的非模块化结构。若改造为 ES module，需要梳理数千处跨函数引用，**极易引入行为差异**，与「功能完全不变」的硬约束冲突。

**结论**：前端只做**低风险的物理拆分**（按功能注释切块为多个 `<script>`，保持全局命名空间与加载顺序不变，运行时行为等价），**不强行引入 ESM**。

## 四、重构方案（分阶段，每阶段可独立验证）

### 阶段 0：建立安全网（必须先做）
当前项目**没有任何测试**，也未引入 pytest。重构前先建立：
- **路由快照测试**：启动 app，断言全部 121 个路由的 `path + method` 与重构前逐一致（基于 `app.routes` 自动生成快照）。
- **关键接口冒烟测试**：对核心 GET 接口做响应/状态码断言。

作用：任何「功能改变」都会被立即检出，使后续拆分可放心进行。

### 阶段 1：后端拆分（核心，收益最大）
保留入口可启动性，逐步将 `main.py` 抽离为包结构：

```
app/
├── main.py              # 创建 FastAPI、注册中间件、include_router、挂载静态目录、uvicorn 入口
├── config.py            # 全部 BASE_DIR / 路径常量 / 环境变量
├── core/
│   ├── auth.py          # auth_middleware、session 管理、current_user
│   ├── ws.py            # ConnectionManager
│   └── storage.py       # 文件读写 / 并发锁等公共工具
├── models/              # 50 个 Pydantic 模型按域拆分
└── routers/
    ├── canvases.py      ├── assets.py        ├── runninghub.py
    ├── prompts.py       ├── jimeng.py        ├── workflows.py
    ├── providers.py     ├── conversations.py ├── generate.py
    ├── shared_folders.py├── history.py       └── ...
```

- 每个 router 使用独立的 `APIRouter()`，在 `app/main.py` 中 `app.include_router(...)`。
- **URL 路径一字不变**，请求/响应模型与状态码不变。
- 拆分顺序建议：先抽 `config` 与 `core`（无路由、依赖最底层），再按功能域逐个抽 router。

### 阶段 2（可选）：前端物理拆分
低风险方案：
- 将 `canvas.js`、`smart-canvas.js` 按现有功能注释切成多个小文件。
- HTML 中按**原顺序**多引几个 `<script>`。
- **不改全局命名空间、不引入 ESM** —— 等价于「把一个大文件按原顺序切成几段拼接」，运行时行为完全一致。

## 五、入口兼容性（重要）

当前启动依赖 `main.py`（`python main.py` / `uvicorn main:app`，端口 3000），且 `scripts/`、`docs/运行说明.txt`、各 `.bat` 启动脚本中可能写死 `main.py`。

**建议**：重构为 `app/` 包后，在根目录**保留一个兼容入口 `main.py`**：

```python
# main.py（兼容入口）
from app.main import app

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=3000)
```

这样所有现有启动命令、脚本、文档**无需任何改动**。

| 项目 | 风险等级 | 说明 / 缓解 |
|------|---------|------------|
| 后端路由拆分 | 低 | 路由快照测试兜底；逐模块拆分逐次验证 |

**回滚策略**：建议每拆一个模块提交一次 commit；任一阶段验证失败可单独回退该提交。

- `main.py`：10,885 行 → 8,388 行；66 个路由迁入 9 个 router 模块，通过 `app.include_router` 注册。

- 根目录 `main.py` 入口保持不变：`python main.py` / `uvicorn main:app`（端口 3000）。

### 9.2 刻意保留在 main.py 的「运行期核心」（策略 A）

以下域**有意保留在 `main.py`**，因为它们共享 **provider 配置 + 由 `reload_env_globals()` 用 `global` 运行时重新赋值的可变全局**（`CHAT_MODELS`/`IMAGE_MODELS`/`VIDEO_MODELS`/`AI_API_KEY`/`COMFYUI_INSTANCES` 等）以及上百个相互调用的生成 helper：

- RunningHub（11 路由）、即梦生成函数、供应商配置/`/api/config`/`/api/models`、生成域（online-image / canvas-image-tasks / canvas-video / canvas-llm / chat / angle / ms-generate / generate）。
- 依赖上述核心的少数路由：素材库 avatar 注册/审核、`/api/workflows/{name}/run`、`/api/comfyui/instances`、`/api/view`、`/api/upload`、`/api/temp-sh/upload`、`/api/cloud-video/upload`、`auth_middleware`、`/ws/stats`、`/static/{page}.html` 与静态挂载。

**理由**：把「运行时重新赋值的模块全局」搬到独立模块，会让该模块在 import 时只持有旧绑定，运行期 `reload_env_globals()` 重新赋值后读到陈旧值 —— 这是路由/模型/认证契约测试**抓不到**的隐性行为变更。在「零行为变更」硬约束下，保留这部分为 `main.py` 的运行期调度核心是合理的架构终态。

### 9.3 最终形态

`main.py` = 运行期核心（env/provider 可变全局 + 生成调度 + 中间件/WebSocket/静态挂载）；其余按功能域清晰拆分到 `app/`。功能 100% 不变。
