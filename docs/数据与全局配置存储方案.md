# 数据与全局配置存储方案

> 日期：2026-07-13  
> 适用范围：MediaForge `data/` 与 `global_config.json` 的后续收口

## 一、目标

MediaForge 当前仍有部分运行时数据保存在本地 JSON 或 Markdown 文件中。为了支持多实例部署、事务写入、权限隔离和可靠审计，应按数据性质选择存储，而不是将所有文件简单迁入同一种介质。

推荐边界：

- PostgreSQL：动态业务数据、用户配置、权限、反馈和系统可变配置
- Redis：登录会话、短期状态和缓存
- 环境变量或 Secret Manager：API 密钥、数据库密码等秘密
- Git 静态资源：内置规则、默认模板和随版本发布的帮助文档
- MinIO：图片、视频、音频、FBX 等二进制文件
- 浏览器内存、IndexedDB 或 `/tmp`：可丢失的中间产物

## 二、当前文件与推荐归宿

| 当前文件 | 当前用途 | 推荐归宿 |
|---|---|---|
| `data/access_control.json` | 用户页面、节点和模型权限 | PostgreSQL |
| `data/announcement.json` | 系统公告 | PostgreSQL |
| `data/api_providers.json` | API 平台、模型和 RunningHub 配置 | PostgreSQL，核心字段结构化，扩展字段 JSONB |
| `data/feedback.json` | 用户反馈和处理状态 | PostgreSQL |
| `data/sessions.json` | 登录 token、用户和访问时间 | Redis；暂时也可使用 PostgreSQL |
| `data/users_registry.json` | 用户注册表 | PostgreSQL `users` 表 |
| `data/users/*/caption_rules.json` | 普通画布 Caption 自定义规则 | PostgreSQL |
| `data/users/*/expand_rules.json` | 用户提示词扩展规则 | PostgreSQL |
| `data/users/*/prompt_libraries.json` | 用户提示词库 | PostgreSQL |
| `data/prompt_libraries.json` | 全局或旧版提示词库 | Git 静态种子或 PostgreSQL 系统提示词库 |
| `data/help_pages/*.md` | 帮助文档 | Git 静态文件或 PostgreSQL，取决于是否允许在线编辑 |
| `data/caption_rules_builtin.json` | 内置 Caption 规则 | Git 静态资源 |
| `data/expand_rules_builtin.json` | 内置扩展规则 | Git 静态资源 |
| `global_config.json` | 存储配额和旧 token 回退 | 配额迁入 PostgreSQL；密钥迁入环境变量 |

## 三、PostgreSQL 数据模型建议

动态数据建议逐步收口到以下表：

```text
users
user_sessions
access_control_policies
announcements
feedback_entries
api_providers
user_caption_rules
user_expand_rules
prompt_libraries
prompt_categories
prompt_items
storage_quota_settings
system_settings
```

### 3.1 API 平台配置

API 平台配置适合采用“核心字段结构化 + 扩展 JSONB”：

```text
api_providers
- id
- name
- protocol
- base_url
- enabled
- is_primary
- config_json
- created_at
- updated_at
```

API key、火山 AK/SK、ModelScope token 不应存入 `config_json`。数据库中最多保存环境变量名称或 Secret Manager reference，秘密本身只从部署环境读取。

### 3.2 用户规则

Caption 和 Expand 规则可以统一建模：

```text
user_rules
- id
- user_id
- rule_type
- name
- content
- enabled
- sort_order
- created_at
- updated_at
```

其中 `rule_type` 可取 `caption` 或 `expand`。

### 3.3 提示词库

```text
prompt_libraries
- id
- user_id
- name
- is_system
- created_at
- updated_at

prompt_categories
- id
- library_id
- name
- sort_order

prompt_items
- id
- category_id
- name
- content
- sort_order
- created_at
- updated_at
```

系统提示词库可使用 `is_system=true`，并由版本化种子脚本初始化。

### 3.4 空间配额

默认配额继续由环境变量提供：

```text
STORAGE_QUOTA_ENABLED
STORAGE_USER_QUOTA_BYTES
```

用户覆盖值存入 PostgreSQL：

```text
storage_quota_settings
- user_id
- quota_bytes
- created_at
- updated_at
```

如果全局开关和默认配额需要由管理页面动态修改，可写入 `system_settings`，但环境变量仍作为部署级默认值。

## 四、Sessions 存储

`data/sessions.json` 保存真实登录 token，是当前最需要收口的文件之一。本地 JSON 存在以下问题：

- 多实例之间无法共享会话
- 并发写入和过期清理不可靠
- 文件泄漏等同于会话泄漏
- 不适合备份或版本控制

首选 Redis：

```text
session:<token_hash> -> user_id / username / last_seen
TTL = SESSION_MAX_AGE
```

如果暂不部署 Redis，可先使用 PostgreSQL：

```text
user_sessions
- token_hash
- user_id
- created_at
- last_seen
- expires_at
```

只保存 token 哈希，不保存明文 token。

## 五、帮助文档与内置规则

### 5.1 帮助文档

如果帮助文档随版本发布且不允许管理员在线修改，应移动到类似目录并纳入 Git：

```text
docs/help/
```

如果保留管理页面在线编辑能力，并要求多实例立即同步，则应迁入 PostgreSQL：

```text
help_pages
- slug
- title
- content
- updated_by
- updated_at
```

### 5.2 内置规则

以下文件属于产品默认资源，不是运行时业务数据：

```text
data/caption_rules_builtin.json
data/expand_rules_builtin.json
```

建议移动到：

```text
app/resources/
```

或：

```text
static/config/
```

这些文件应纳入 Git、启动时只读，不能被用户接口覆盖。

## 六、global_config.json 处理

`global_config.json` 最终应下线：

- `storage_quota` 迁入 PostgreSQL
- 默认配额继续由环境变量提供
- 用户配额覆盖写入 `storage_quota_settings`
- `modelscope_token` 旧回退逻辑删除
- 所有秘密只从环境变量或 Secret Manager 读取

迁移完成前，它仍是运行时配置文件，不能直接删除，但必须加入 `.gitignore`：

```gitignore
global_config.json
```

不得将包含真实用户 ID、配额或 token 的文件提交到代码仓库。

## 七、目标目录形态

最终 `data/` 不再承载可变运行时主数据：

```text
app/resources/             # Git 管理的内置规则
docs/help/                 # Git 管理的静态帮助文档
PostgreSQL                 # 动态持久数据
Redis                      # sessions 和短期状态
MinIO                      # 二进制文件
环境变量或 Secret Manager   # 密钥
/tmp                       # 可丢失中间文件
```

运行时本地目录只允许保存缓存和临时文件，服务重启或实例替换后可以安全丢弃。

## 八、迁移优先级

建议按风险和依赖顺序推进：

1. `sessions.json` 和 `users_registry.json`
2. `access_control.json` 和 `global_config.json`
3. `api_providers.json`
4. 用户 Caption、Expand 和 Prompt Library
5. announcement、feedback 和可编辑 help pages
6. 将内置规则整理为 Git 静态资源

每一类迁移都应包含：

- PostgreSQL 表结构和索引
- 一次性、可验证的迁移脚本
- 运行时读写切换
- 本地 JSON 回退移除
- 迁移数量与数据库数量对账
- 明确的回滚或备份方案

## 九、结论

MediaForge 的目标不应是“保留一个更大的 data 目录”，而应是让存储职责清晰：

- 动态数据进入 PostgreSQL
- 会话进入 Redis 或 PostgreSQL
- 秘密留在部署环境
- 内置资源由 Git 管理
- 二进制文件进入 MinIO
- 中间产物只存在于客户端或临时目录

完成上述迁移后，本地可变 JSON 主存储可以全部下线。
