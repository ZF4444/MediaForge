# 数据迁移说明

> 更新日期：2026-07-13  
> 适用范围：将旧版 JSON、本地媒体文件和用户业务数据迁移到 PostgreSQL 与 MinIO。

## 一、迁移脚本

迁移由三个一次性脚本完成：

| 顺序 | 脚本 | 作用 |
| --- | --- | --- |
| 1 | `scripts/migrate_json_config_to_postgres.py` | 将全局配置、用户注册表、会话、用户设置和帮助文档迁入 PostgreSQL |
| 2 | `scripts/migrate_local_files_to_minio.py` | 将 `assets/*` 文件迁入 MinIO、登记 `files` 表，并把旧媒体引用改写为 `file_id` |
| 3 | `scripts/migrate_business_metadata.py` | 将历史记录、资产库、对话和画布迁入 PostgreSQL 业务表 |

必须按上述顺序执行。配置迁移会先建立用户数据；文件迁移会生成业务元数据所依赖的 `file_id`。

## 二、执行前准备

执行前确认：

1. PostgreSQL 和 MinIO 已启动且可访问。
2. 已配置 `DATABASE_URL`。
3. 已配置 `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`。
4. 已备份 PostgreSQL、`data/`、`assets/` 和 `global_config.json`。
5. 迁移期间停止应用写入，避免 JSON 和数据库同时变化。
6. 在项目根目录执行所有命令。

检查存储连接配置：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python -c "from app.services.storage import storage_enabled, metadata_db_enabled; print('storage_enabled=', storage_enabled()); print('metadata_db_enabled=', metadata_db_enabled())"
```

两项均应输出 `True`。

## 三、迁移配置数据

执行：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_json_config_to_postgres.py
```

脚本迁移以下数据：

- `data/access_control.json` -> `app_settings.access_control`
- `data/announcement.json` -> `app_settings.announcement`
- `data/api_providers.json` -> `app_settings.api_providers`
- `data/shared_folders.json` -> `app_settings.shared_folders`
- `data/prompt_libraries.json` -> `app_settings.system_prompt_libraries`
- `global_config.json` 中的存储配额 -> `app_settings.storage_quota`
- `data/users_registry.json` -> `users`
- `data/sessions.json` -> `user_sessions`
- `data/feedback.json` -> `feedback_entries`
- `data/users/*/caption_rules.json` -> `user_settings.caption_rules`
- `data/users/*/expand_rules.json` -> `user_settings.expand_rules`
- `data/users/*/prompt_libraries.json` -> `user_settings.prompt_libraries`
- `data/help_pages/*.md` 和 `data/help.md` -> `help_pages`

该脚本没有 dry-run 参数。写入主要使用 upsert，可在确认源数据未变化的情况下重新执行。成功后会输出各数据类型的迁移数量和目标表总数。

## 四、迁移媒体文件

### 4.1 迁移范围

`migrate_local_files_to_minio.py` 固定扫描全部分类：

- `assets/input/`
- `assets/output/`
- `assets/library/`
- `assets/uploads/`

它会：

1. 上传尚未迁移的文件到 MinIO。
2. 在 PostgreSQL `files` 表登记文件。
3. 修复数据库记录存在但对象缺失的文件。
4. 将用户 JSON 中的旧媒体 URL 收口为 `file_id`。
5. 在 `scripts/reports/` 生成完整 JSON 报告。

脚本不会删除本地原文件。

### 4.2 Dry-run

先执行全量扫描，不写 MinIO、PostgreSQL 或 JSON：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_local_files_to_minio.py --dry-run
```

重点检查输出和报告中的：

- `scanned`
- `planned`
- `skipped`
- `errors`
- `warnings`
- `metadata.files`
- `metadata.changed`

### 4.3 正式迁移

确认 dry-run 无误后执行：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_local_files_to_minio.py
```

命令行只保留 `--dry-run`。正式执行始终处理全部分类、改写全部支持的元数据，并自动生成报告，避免分批参数造成遗漏或状态难以对账。

文件归属规则：

- 只被一个用户引用：归属该用户。
- 被多个用户引用：归属 `anonymous`。
- 没有用户引用：归属 `anonymous`。

## 五、迁移业务元数据

文件迁移成功后执行：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_business_metadata.py
```

脚本读取：

- `data/users/*/history.json`
- `data/users/*/asset_library.json`
- `data/users/*/conversations/*.json`
- `data/users/*/canvases/*.json`

并写入：

- `history_records`、`history_record_files`
- `asset_libraries`、`asset_categories`、`asset_items`
- `conversations`、`conversation_messages`、`conversation_message_files`
- `smart_canvases`、`smart_canvas_nodes`、`smart_canvas_node_files`

只有能在 `files` 表中找到的 `file_id` 才会建立文件关联。脚本没有 dry-run 参数；执行结束会输出迁移计数和数据库表总数，并检查画布是否成功写入。

该脚本应按一次性迁移使用。画布和对话会覆盖同 ID 数据，但历史记录会生成新 ID；不要直接重复执行，否则可能产生重复历史。需要重跑时应先恢复迁移前的 PostgreSQL 备份。

## 六、完整执行命令

测试环境和生产环境使用同一顺序：

```bash
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_json_config_to_postgres.py
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_local_files_to_minio.py --dry-run
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_local_files_to_minio.py
UV_CACHE_DIR="$PWD/.uv-cache" uv run python scripts/migrate_business_metadata.py
```

生产环境应在维护窗口执行，并在每一步确认无错误后再继续。

## 七、验收

### PostgreSQL

- `users`、`user_sessions`、`app_settings`、`user_settings` 有预期数据。
- `files` 记录的 `bucket`、`object_key`、`legacy_url` 和 `user_id` 正确。
- 历史、资产库、对话和画布业务表数量与脚本输出相符。
- 业务文件关联引用的 `file_id` 均存在。

### MinIO

- 抽样对象大小与本地文件一致。
- 图片、视频和音频可以正常预览或下载。
- 文件迁移报告中的 `errors` 为 `0`。

### 应用

- 用户可以正常登录。
- API 设置和访问控制配置正常。
- 历史记录与资产库可以展示旧文件。
- 对话附件和画布节点可以正常加载媒体。
- 帮助页面内容正常。

## 八、失败与回滚

任一步骤失败时：

1. 停止后续迁移和应用写入。
2. 保存终端输出及 `scripts/reports/` 报告。
3. 根据失败阶段恢复 PostgreSQL 备份。
4. 如 JSON 被文件迁移脚本改写，恢复 `data/` 备份。
5. 不要立即删除 MinIO 对象，先完成问题定位和数据对账。

本地 `assets/*` 文件默认保留，因此文件读取仍有回退基础。确认 PostgreSQL、MinIO 和应用验收全部通过后，再单独安排旧文件清理。
