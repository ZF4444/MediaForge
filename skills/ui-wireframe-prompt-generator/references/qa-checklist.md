# QA 检查清单

回复前静默检查：

- 是否检查了 `主题`、`背景`、`主视觉`、`UI皮肤`、`图标` 五个槽位；首次发现任一缺失或含义不明确时，是否仅追问而未提前生成描述词。
- 当前请求若已追问过一次，是否避免再次追问，并对用户仍未补充的槽位按推断边界完成生成。
- 正确识别目标线框图，没有把参考图当成目标布局。
- 保留画幅方向、区域、文字、数字、间距、组件数量、顺序、对齐关系和状态。
- 覆盖顶部、上半屏、中部、下半屏和底部区域。
- 每个新增背景、主视觉、容器、按钮或重要图标都包含相对位置和所属区域。
- 背景是否交代远景/中景/前景或全屏底图、空间深度、明暗分区、虚实程度和主要光源，且没有虚构被 UI 完全遮挡的场景。
- 主视觉是否交代位置、占比、朝向、轮廓、组成部件、颜色、材质、状态、投影和遮挡关系；无证据时是否降级为类别描述或“无独立主视觉”。
- UI 皮肤包含形状、填充、材质、边缘、体积、文字处理和相关状态差异。
- 图标是否覆盖顶部资源/功能、主题入口、卡片和奖励格中的不同物品、购买货币、品质框、角标、底部导航和红点等重要占位。
- 图标内容是否先匹配用户的图标约束和 `project-style-reference.md` 中与组件语义兼容的既有类别、容器或状态规则；仅在没有对应类别时，才依据占位框、文字和位置做最小范围的类别补全。
- 图标内容是否严格服务于相邻文字和所属组件，未由主题、背景或主视觉自由扩展无关物品、角色或机制。
- 重复卡片或占位格是否先概括共同样式，再写明有意义的逐项配色、图标、价格、数量和状态差异。
- 在证据允许时，重要占位框是否具体化为“类别＋形状＋颜色＋材质”的可生成对象，而非“某个图标”或“一些装饰”。
- 特效不会遮挡文字、价格、数量、按钮或图标。
- 是否每个补充元素只描述一次，且先完整覆盖主要区域，再压缩重复细节。
- 没有明确对象的字段是否仍然保留，并使用忠实的空值描述而非虚构内容。
- 不包含无关样例内容、不支持的专有名称、空泛评价、像素坐标或布局重设计措辞。
- 描述词是否只陈述成品 UI 的确定外观，未出现“线框图、参考图、推断、优先、依据、保留、保持、占位、自动推断”等来源、过程或不确定性措辞。
- 最终输出符合四字段单段格式合同。
