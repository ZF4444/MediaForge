# 推断边界

## 证据优先级

1. 目标线框图：画幅、结构、文字、数字、位置、数量、层级和状态。
2. 用户明确提供的文字和不可变更/禁止项约束。
3. 用户针对具体槽位提供的参考图片。
4. `project-style-reference.md` 中稳定或匹配的条件规则。
5. 通用游戏 UI 语义。

## 参考图片

只提取请求槽位对应的视觉属性。主题图可以提供题材和氛围；背景图可以提供空间深度和光线；皮肤图可以提供容器、边框、材质、字体和状态；图标图可以提供物体类别、视角、材质、品质底板和光效。绝不导入无关的布局、文案、数量、角色、商品或状态。

## 图标选择

图标内容按以下顺序确定：用户明确提供的图标约束或图标参考；`project-style-reference.md` 中与组件语义匹配的既有图标类别、容器和状态规则；线框占位框、相邻文字和所属组件共同支持的最小类别推断。项目风格 Reference 中只有渲染规则而没有具体物体类别时，只复用其材质、描边、底板、光影或状态，不将其视为具体图标内容。不得仅凭主题、背景或主视觉扩展出与页面功能无关的图标、物品、角色或机制。

## 缺失信息

当线框语义或项目风格能够支持时，可以进行合理推断。无法支持精确身份时，使用类别级描述，例如“医疗十字图标”或“银灰色圆形时钟图标”。不要编造专有名称、身份、叙事、品质或机制。没有明确主视觉证据的页面可以直接使用“无独立主视觉”，不要强行加入角色或场景。原始训练描述词仅用于离线生成和维护项目风格 Reference，不作为运行时输入或检索语料。

## 冲突处理

用户明确约束优先于推断内容，但不能覆盖线框图的不可变结构。如果参考图片与线框图冲突，只借用兼容的视觉语言，并保留线框图结构。
