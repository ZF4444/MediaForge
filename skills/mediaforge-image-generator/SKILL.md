# MediaForge AI 图片生成

把用户的图片需求转换为可确认、可追踪的 AI 生图任务。沿用平台“能力发现 → 参数读取 → 画布提案 → 确认执行 → 结果回传”的链路；使用普通图片模型，不套用 X2 场景资产提示词规则。

## 能力与适用边界

- 使用 `semantic_type="image_generation"`，能力为注册表实际返回的 `image.text_to_image`；画布中的“AI生成”引擎值为 `api`，图片模式为 `apiKind="image"`。
- 普通图片模型用 `connection_id` 和 `model_id` 定位，`resource_id` 留空。不能因为连接名称含 RunningHub 或某个供应商品牌就判断引擎；以注册表中的能力和 target 类型为准。
- 用户明确选择 ComfyUI、RunningHub 应用或 X2 工作流时，改用对应工作流 skill，不将其静默转换为 AI 生图。
- 以当前实际开放的工具和系统规则为准。画布读取、能力发现、参数读取或提案工具不可用时，说明受限阶段，可交付已准备的提示词及用户明确要求的参数；不编造已配置模型、节点或执行状态，不绕过平台直连供应商。
- 文生图与图生图共用上述能力和节点；不能根据 `image.text_to_image` 的名称判断模型是否支持图片输入。图生图还需核实所选 target 的 `image_input` 契约，并绑定实际图片。

## 模式路由

- 用户仅按文字描述创作且不要求使用已有图片：文生图，不附加参考图片连接，不自动拿选中节点、旧输出或历史输入作参考。
- 用户要求“基于这张图”“改成”“保持图中主体”或多图融合：图生图，先读 [references/image-to-image.md](references/image-to-image.md)，确认图片来源、索引、顺序和修改目标。只有图片但缺少操作意图时，询问要保留和修改的内容。
- 图片仅用来分析、描述或反推提示词时，先完成该任务，不自动提交图生图。要求蒙版或精确区域编辑时，说明当前本 skill 没有专用蒙版绑定，不能把蒙版当普通参考图冒充局部编辑。
- “先生成，再基于结果修改”分阶段处理：等首个任务成功且原图进入画布后，再绑定真实输出并提出下一次图生图提案。

在平台内使用 `read_canvas_skill_file` 按需读取本 skill 目录中的相对路径；参考文档不要求执行脚本。

## 输入与模型选择

1. 区分只要提示词、只配置节点、实际生图。用户说“生成/画/生图”即准备运行；“只要提示词”完成文本后结束，“先配置、不运行”不加入运行动作。
2. 提取主体、用途、风格、构图、可见文字及用户明确要求的模型、比例、分辨率、质量和数量。保留用户原意、数量和文字，不主动附加透明背景、等距视角或游戏资产风格。缺少可识别的画面描述或明确要求冲突时，集中询问必要信息；可选参数未指定时沿用所选模型的实时默认值。
3. 调用 `read_canvas_context`，识别用户明确指定的节点及其当前模型、参数和输入连接；图生图还需读取参考图片节点及其 `images`。上下文被截断且目标不可见时，按真实节点 ID 定向读取，不凭空补全。
4. 调用 `read_capability_registry`，只在 `image.text_to_image.targets` 中选择 `enabled=true` 的普通模型。将所选 target 的 `connection_id`、`model_id` 原样保存，不能把显示名、上游模型名或旧环境 ID 当作稳定 ID。
5. 用户指定模型时必须匹配该模型；同名多连接且无法消歧时列出候选询问。未指定模型时，优先沿用用户明确指定节点上仍已启用且支持本次输入链路的模型；否则只有一个候选可直接选择，多个候选则提供简短选项，不擅自选用第一个或推测价格、质量排序。目标缺失、禁用或不支持参考图链路时说明原因，不静默换模型。

## 参数与提示词

选定模型后，调用 `read_capability_parameters(capability, connection_id, model_id)`；即使复用已有节点，也要读取契约。模型改变后重新读取，不沿用上一模型的选项与范围。

- 以返回的 `fields`、`role`、`options[].value`、`default`、`min/max/step` 和 `params_path` 为准。显示标签用于解释，提交值保留原始类型；不要把 label 当作 value。
- 提示词写入 `role="prompt"` 的字段，常见 ID 为 `prompt`。根据用户描述整理清晰的画面描述；用户要求原样使用时不重写。若没有可识别的提示词字段，停止并说明契约缺失。
- 比例、分辨率、质量和数量只能使用当前契约支持的值。用户指定值不受支持时说明可选值，询问后再修改；不要静默取整、缩减张数或把比例写进提示词来冒充参数设置。
- 未指定参数保留模型默认值；新节点需要显式落实这些默认值时，从当前契约复制。复用节点则保留仍符合契约、且适用于本次任务的已有设置。不要假设每个模型均支持 `4k`、`high`、透明输出、负面提示词或种子。
- `provider_id`、`model` 等选择字段由稳定 target 绑定；不要把模型显示名填入参数。新建节点时按字段 ID 平铺原始值，由后端按 `params_path` 组装为 `runSettings`，不要手工构造供应商请求。

在准备提案前，读取 [references/canvas-contract.md](references/canvas-contract.md)，按其中的新建或复用路径填写计划。参考图片通过 `relation="input"` 的画布连接提供，不填入模型参数字段或提示词 URL。

## 提案、执行与回传

1. 默认创建新的图片生成节点，避免覆盖其它作品。仅在用户明确指定已有节点且节点为 `api` 图片生成节点时复用；复用时遵守参考文档中的参数更新规则。将 `capability`、`connection_id`、`model_id` 放在 `SemanticNode` 专用字段，不塞进新节点的 `params`。
2. 调用 `propose_canvas_patch`，使用 `canvas.create_node` 或已有节点更新步骤；图生图在运行前按参考文档连接图片并排除未选图片。生图请求还需在同一计划中加入 `canvas.run_node`，指向创建步骤 ID 或真实节点 ID；普通单图任务不使用 `canvas.run_group`。
3. 简短呈现所选连接/模型、提示词、关键参数和数量；图生图还须列出参考图顺序及选中的图片。提案返回 `awaiting_confirmation` 只表示等待平台确认，不能声称节点已创建或任务已启动。遵守平台现有确认流程，不在规划阶段调用执行工具；确认后由平台执行器应用提案并提交任务。
4. 根据真实任务事件或工具返回报告节点、所用模型、状态、任务/操作 ID。排队或运行中仅报告已知阶段；只有成功事件及实际输出资产返回后，才交付可访问的图片引用和实际张数。无法继续查询时保留任务 ID，明确最终结果尚未获知。
5. 失败时保留提示词和参数，说明失败发生在能力匹配、参数校验、提案、确认、提交还是生成阶段。提交结果不明时优先通过已开放的查询能力核实已有任务；没有查询能力则报告未知状态，不重新提交。用户要求重试时，先确认没有仍在运行的重复任务；授权或额度错误不自动循环重试。

只查询、只准备提示词、缺少必需输入或执行能力受限时，交付对应阶段的结果并说明尚未执行；实际生图请求在可执行条件齐备时应推进到提案，不停留在提示词输出。
