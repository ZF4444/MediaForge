# X2 场景单体文生图适配器

## 必要输入与交互策略

适用于建筑、工事、资源设施、地形、植被组和环境道具等单一环境资产。运行前收集两项输入：

- **场景单体描述**：足以识别主体及用户明确要求的组件、数量、颜色、材质、结构、观察方向和可见文字。
- **输出图像比例**：例如 `1:1`、`3:2` 或 `2:3`，用于安排画面空间，不代表主体自身的结构比例。

先检查当前请求和已有对话，只沿用明确适用于本次资产的信息，用户最新指定优先；不得自动沿用上一资产的描述或比例。缺失或无法识别的输入一次性询问，用户补充后只追问仍未明确的部分，不自行选用默认比例。

明确要求相互冲突时，询问用户取舍；多个不相关主体无法组成连贯资产时，询问主资产或主体之间的关系。不得擅自删除对象、折中明确要求或强行拼成复合资产。输入缺失、冲突未解决或资产范围未明确时，只进行澄清，不提前改写或执行。

材质、颜色、视角、光照等未指定细节按提示词规则补全，不扩大必填项。背景和主体之外的周围地面默认透明，不为此追问；用户明确指定背景或地面时分别保留。

## 端到端运行流程

1. 判断用户是否只要提示词。收集上述两项输入，并解决冲突和资产范围问题。
2. 输入齐全后，完整阅读 [X2 场景资产提示词规则](x2-scene-asset-prompt-rules.md)，提取主体、明确约束及画幅比例。比例只用于内部构图和工作流参数。
3. 组织主体与组件的位置，补全必要结构和表面细节，处理可见文字及光照，形成一个中文段落，并按提示词规则中的“内部最终检查”自检。
4. 用户明确只要提示词时，按提示词规则中的“提示词输出约定”返回并结束；生成请求则继续解析 X2 资源和实时参数契约，不在重写完成后提前结束。
5. 按下文“适用目标与运行前检查”和“X2 画布映射”准备节点及参数。无法唯一匹配已启用的 X2 资源时，说明候选或缺失原因并暂停，不使用普通文生图模型或其它工作流替代。
6. 读取画布上下文。只有用户明确指定且适合本次任务的已有节点才更新复用，否则创建节点，避免覆盖其它资产；将运行动作纳入画布提案，等待平台确认后由执行器运行。
7. 根据平台实际返回的信息报告工作流名称、执行状态、任务/操作 ID 和输出资产引用。已提交或排队不等于已生成；异步运行保留可查询 ID。
8. 参数校验、资源不可用或执行失败时，保留重写提示词，说明失败阶段、具体原因和所需补充信息。提交结果不明时先查询已有任务，避免重复提交；不自动反复发起生成。

## 适用目标与运行前检查

在能力注册表中匹配显示名为 `X2场景单体文生图` 的已启用图片工作流。资源的 `resource_id`、`connection_id` 和能力名必须每次从注册表读取；数据库中的资源 ID 可能因环境迁移而变化，不能写死。选中后调用 `read_capability_parameters`，以实时返回的字段定义为准。

当前数据库快照显示该工作流的主要字段如下，字段 ID 仅用于理解和核对，实际提交仍以参数工具返回值为准：

| 语义 | 字段 ID | 类型 | 默认/示例 |
| --- | --- | --- | --- |
| 提示词 | `492::text` | `PROMPT` | 工作流示例提示词 |
| 画幅比例 | `13::aspect_ratio` | `LIST` | `1:1 (Square)` |
| 输出像素量 | `13::megapixels` | `FLOAT` | `0.3` |
| CFG | `496::value` | `FLOAT` | `3` |
| 采样步数 | `497::value` | `INT` | `25` |
| 批量数量 | `474::batch_size` | `INT` | `4` |

除提示词和用户明确给出的比例外，保留工作流默认值；不要自行调整 CFG、采样步数或批量数量。比例必须使用参数工具返回的原始选项值（例如 `1:1 (Square)`），不能自行改写成未注册的 `1:1`。

## 画布映射

- 节点使用 `workflow_generation`，能力和 target 标识来自注册表。
- 提示词按参数工具返回的 `params_path` 和字段 ID 传入；平台后端会将其归位到 `runSettings`，不要手工构造 `rhParams` 或 `{value: ...}`。
- 该工作流没有图像输入字段时，只传提示词、比例及用户明确指定的参数；不得凭空连接参考图。
- 先提出画布 patch，获得用户确认后再运行节点。运行结果以平台任务事件和输出资产为准。
